# Obsidian Memory Tree — Savant's Second Brain> **Design Decision**: After reviewing OpenHuman, GBrain (garrytan/gbrain), and our own codebase, the chosen architecture is **Markdown as the human interface, LSM+HNSW as the system of record** — Option C (bidirectional with scope rules).  > > GBrain proves markdown-first works for human-AI shared memory, but its git-as-source-of-truth approach requires `db_only` storage tiering at 100K+ files. Savant avoids this by keeping the high-performance LSM+HNSW as the canonical store and projecting a markdown view on top, with selective bidirectional sync.>> Deep research prompt filed at `docs/deep-research/obsidian-memory-tree-research.md` — send this to Gemini before implementation begins.## Core InsightSavant already has a world-class memory architecture: LSM + HNSW vectors + concept graph + distillation + dream consolidation. But it's invisible — locked in binary rkyv blobs and CortexaDB collections. The user cannot browse it, trust it, edit it, or explore the connections between memories.OpenHuman talks about an "Obsidian Wiki" but doesn't actually write markdown files either. Savant can beat them by making its superior memory substrate **fully transparent through Obsidian**.The agent lives in a markdown vault the user can open at any time, see exactly what the agent knows, how it connects concepts, and drill down from high-level summaries to raw conversation data. Edits the user makes in Obsidian flow back into the agent's memory graph.---## What Exists (No New Work Required)### Shadow Memory Graph- `ReflectiveMemory` with `Concept` nodes and `Relation` edges- Concept types: Episodic / Semantic / Identity- Relation types: `is_a`, `part_of`, `contradicts`, `evolved_into`, `superseded_by`### Raw Episodic Data- LSM-stored `AgentMessage` with ids, sessions, roles, content, tool calls, tool results, timestamps- 100% crash-recoverable via WAL- Archived and consolidatable via Dream NREM cycles### Extracted Knowledge- `DistilledTriplet` (subject-predicate-object) from LLM extraction pipeline- `Entity` graph (Project, Service, Person, Credential, Tool, File, Config)- Shannon entropy scores on all content### Personality Grounding- OCEAN personality traits per agent- `PromotionEngine` scores every memory for promotion worthiness- Identity-level promotion triggers SOUL.md mutations### Dream Pipeline (Background Consolidation)- NREM: dedup + contradiction resolution + compression- REM: cross-domain concept recombination- Vendi Score diversity filtering- All produce structured results ready for tree injection---## What Needs Building### A. The Canonicalization Pipeline (Adapt from OpenHuman Pattern)Not all source data should go straight into the vault. We need adapters per source type:```textRaw source (AgentMessage, DistilledTriplet, Concept, etc.)  → CanonicalisedSource { markdown: String, metadata: Metadata }  → Chunker (split at semantic boundaries, ≤3k tokens)  → Scorer (cheap metrics first, LLM-only on borderline)  → Vault Writer (write .md, update INDEX, update backlinks)```**Key design decisions**:- Deterministic chunk IDs via SHA-256 of source_kind + source_id + seq + content (prevents duplicates on re-sync)- Two-tier scoring: cheap signals (token count, entropy, mention frequency) first; LLM scorer only on chunks scoring between 0.15-0.85- Existing `PromotionEngine` scores reused for chunk admission decisions**What to keep from OpenHuman**:- The canonicalize adapter trait pattern (one impl per source type)- Deterministic chunk IDs for idempotency- Cheap-signals-first scoring**What to do differently (better)**:- Savant already has `PromotionEngine` with OCEAN personality weighting — use this instead of a flat scoring system- Savant has Vendi Score from the Dream engine — use this for diversity filtering of what goes into the vault- Savant's LSM + HNSW is the source of truth; markdown is a *view*, not the primary store---### C. Bidirectional Sync (Vault → Agent)If the user edits a `.md` file in Obsidian, the agent should detect the change and update its internal memory state.**Mechanism**:1. File watcher on the vault directory (reuse existing `notify`-based watcher in `crates/core/src/fs/`)1. On change: parse the modified markdown → diff against last-known state → emit memory update event1. Agent receives event → updates concept graph / entity store / personality as appropriate**Scope constraints**:- User edits to `Episodic/*.md` → ignored (you can't change the past)- User edits to `Semantic/Concepts.md` → parsed, concept graph updated- User edits to `Identity/Personality.md` → OCEAN scores updated, evolution score recalculated- User edits to `Identity/SOUL.md` → blocked by immutable sections (same as dashboard)- User adds new `.md` → NO (don't want hallucinated memories injected via file write)---### D. Dashboard Memory Tree ExplorerExtend the existing `/evolution` dashboard page with a live vault browser:```textMemory Tree tab in dashboard:├── Tree View → expandable hierarchical navigation of vault structure├── Graph View → D3/Three.js force-directed graph of concept relations│   (backed by existing ReflectiveMemory concepts + relations)├── Search → semantic search across both vector store and markdown vault└── Drill-down → clicking a concept shows:    ├── Concept metadata (type, first/last seen, mention count)    ├── Connected concepts (with relation type + weight)    ├── Source sessions (links to raw transcripts)    └── Evolution impact (has this concept triggered SOUL.md mutations?)```The graph view is the killer feature: it renders the `ReflectiveMemory` graph that *already exists in code* as a visual node-edge diagram the user can explore in real time.---### E. Memory Tree Prompts in Heartbeat LensesExtend the existing heartbeat lenses (already have `LENS_EVOLUTION`, `LENS_IDENTITY`, etc.) with:```textLENS_MEMORY_TREE:---FOCUS: MEMORY_TREE (Structural Self-Awareness)- Your memory tree is at workspaces/{name}/memory-vault/.- Review your concept graph. What pattern connects nodes that hasn't been surfaced?- Are there orphan concepts — knowledge stored but not linked to anything?- Would merging two related concepts strengthen your understanding?- Propose a new relation: "This concept evolved_into that concept."```This makes the memory tree self-healing: the agent notices disconnected nodes during idle heartbeat cycles and proposes cross-links via mutation proposals.---## Implementation Phases### Phase 1 — Vault Writer (Core Output)**Effort**: ~1 week1. The vault is a human-readable projection. If the vault is deleted, the agent regenerates it from memory.1. **Deterministic, idempotent writes.** Same memory state always produces the same markdown. Re-syncing doesn't duplicate content.1. **WikiLinks are first-class.** Every entity link is a `[[WikiLink]]` that works in both Obsidian and the dashboard graph view.1. **Bidirectional sync is scoped.** User edits can update the semantic layer but never the raw episodic layer. The agent can learn from user edits but cannot hallucinate memories from file writes.1. **Self-healing via heartbeat.** The agent monitors its own memory tree and proposes structural improvements during idle cycles
